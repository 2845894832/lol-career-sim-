# 决策记录规则

1. **只在用户点头后写 ADR**：还在讨论的留在 `.scratch/<feature>/issues/` 的 ticket 里，ADR 只记已经定死的。
2. **写之前先找出处**：要么用户原话（哪天、哪一句、第几轮），要么 ticket 号；找不到就不许写「已定」。
3. **新 ADR 必带四个字段**：决定 / 日期 / 出处（用户原话或 ticket 号）/ 待确认项。「出处」指决定的核心那句；具体数值或实现若没有单独的用户原话，列进「待确认项」。
4. **指不到用户哪一句的**：文件头加 `> 出处未确认`，文末写「依据：无记录 / 仅 AI 推断」，状态只能是 `待确认`。
5. **发现编造**：不改写决定内容；状态改 `待确认`（要换方案就另写一条 `superseded` 推翻它），原文与日期保留，不删历史。
6. **用户否认过的**：状态改 `待确认`，正文照留，加一段「用户 X 年 X 月 X 日指出未决定，见 ticket N」。
7. **ADR 里的「已定」只表示用户确认过**，不表示 AI 觉得合理。
8. 本规则 2026-11-05 由 AI 起草，**未经用户确认**。
