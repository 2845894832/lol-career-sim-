# 0009 · 事件一周最多一个，且必须先选后结算

- 状态：已定
- 日期：2026-11-04（回填；决定实际做出于 2026-10-28 ~ 11-04 的会话中）
- 出处：用户原话 · 2026-10-28 21:18「3 个行动 + 1 个事件」（T41）、22:03「度过本周就是三个行动点加事件」（T47）；「先选后结算」是交互实现，用户未单独表态

## 背景

事件是唯一的内容载体；如果一周多个，240 周的内容量要翻倍。

## 决定

结周抽一个事件 → 停在浮层等选择 → 应用后果 → 才允许继续结周/清空格子。

## 考虑过的替代方案

① 一周两个事件（内容翻倍 + 节奏拖）② 只有关键周出事件（弱化「每周有故事」的预期）

## 后果

`pendingEvent` 阻塞 `endWeek`/`clearSlot`/`selectAction`，任何新交互都要处理它。

## 证据

`src/core/reduce.ts:108` 起；2.3 的 drawEvent 七步抽取。
