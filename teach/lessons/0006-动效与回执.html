第 6 课 · 动效与回执

动效只解释刚才发生了什么

你的浮层现在是直接出现的：点「结周」→ 一秒后的结果页凭空盖上来。 玩家不会觉得快，只会觉得不知道发生了什么。 动效能补上这一秒，但它只能干一件事：说明哪一下导致了哪一下。

这一课只有一条规则：动效必须能回答「刚才那一下，是从哪儿来到哪儿去」。回答不了，它就是在拖时间——删掉。

为什么是 160ms，不是 600ms

项值理由
浮层时长 120–200ms 短于 100ms 看不出是在「发生」，长过 300ms 像卡了一下。这是经验区间，不是标准值
位移 ≤ 8px 位移只是提示方向（从下面上来）。飞入、缩放、旋转都在抢注意力
数字变化 0ms 六维数字滚动、名次跳动，都会让人读不准。数字直接换

必须留一条关掉的路

有人会因为动效头晕、恶心——这不是少数派问题。WCAG 2.2 的 SC 2.3.3 动画来自交互 说的是：由交互触发的动效必须能关掉，除非它本身就是功能的一部分。 官方给的达标技术就一条：C39——用 prefers-reduced-motion 查询把动效去掉。

落地就三行：

@media (prefers-reduced-motion: reduce) {
  .pop { transition: none; transform: none; }
}

你如果不想写这段，也可以：动效做得足够小（只淡入、不动位置），那样在大多数情况下不会触发不适——但那不满足 SC 2.3.3。

两道题

1. 结果浮层「淡入」和「从下往上滑」两种，你选哪个，为什么？

都不是必须的——但如果只留一个，选淡入。位移（滑入）会让前庭敏感的人不适，而 淡入传达「这一层是新的」已经够用。真要位移，控制在 8px 内，并在 reduced-motion 下归零。

2. 六维数字结周后从 45 变成 47，要不要做个滚动？

不要。滚动过程中数字是错的——玩家会在 46 那一帧看到它，然后误记。 数字直接换，用颜色或符号标出「变了」（比如短暂的绿点），那才是信息。
