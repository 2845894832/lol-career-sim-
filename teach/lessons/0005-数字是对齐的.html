第 5 课 · 数字与排版

数字是拿来比的，不是拿来读的

你那一行现在是：「段位 大师 第 6929 名 · 体力 60/100 · 伤病 0/3 · 金钱 0」。 玩这周的目的是比较——排名掉了多少、钱够不够、伤到几了。比较的前提是数字能竖着对齐， 而你现在四个数字用的是比例字形，每个数字宽度不同，连自己那一行都对不齐。

这一课只有一条规则：凡是会被拿来比较的数字，必须能竖着对齐——等宽数字、靠右、小数位一致。做不到这三点，玩家就只能一个个读，不能一眼比。

先看见它歪在哪

下面是你这局里的几种数字。点两个开关，看它们在做什么：

第 6929 名段位 大师
第 512 名段位 宗师
第 89 名段位 王者
第 1 名段位 王者
体力 60/100伤病 0/3
金钱 1250金钱 80

左边那列是名次，右边是同时读到的另一个数。两个开关都关掉时，是「比例数字 + 左对齐」——也就是你现在的写法。

三个动作，各有各的毛病

动作解决什么不解决什么
等宽数字 每个数字占一样宽，1 不再比 8 窄 位数不同还是长短不一（89 与 6929 差两位）
靠右对齐 个位落在同一条竖线上，位数差别一眼看出 字形还是比例的话，小数点对不齐
小数位一致 5.6 与 14.6 不要写成 5.62 与 14.6 ——这一条只能你自己盯

等宽数字在 CSS 里是一行：font-variant-numeric: tabular-nums。 规范的原话是「所有的数字都是同样大小，让它们能像表格里一样容易对齐」 （MDN · font-variant-numeric）。

中文里还有一格空隙

数字和汉字挨着的时候（「第 6929 名」「12 体力」），中文排版的惯例是留一点空隙，不要粘死。 这条写在 W3C 的中文排版需求（clreq）里； CSS 正在加一个属性专门做这件事（text-autospace， CSS Text 4，还是草案）。

你现在是手打空格：有的地方有（「第 6929 名」），有的地方没有（「60/100」「0/3」）。 手打不算错，但规则得定下来——以后统一用哪种，写进 P3 的规格表里。

三个数字

项值理由
等宽数字tabular-nums所有会排成列、会被比较的数字都加，包括句子里的名次
数字列宽固定，别用内容撑宽度随内容变，一换数据整列就跳，玩家刚记住的位置全废
小数位同列统一胜率一列要么都 1 位（60%、34%），要么都 2 位（60.0%）

两道题

1. 你那一行「体力 60/100」里的 60/100，最大的排版问题是哪个？

不是「没空格」，是它和右边的「伤病 0/3」不是同一套写法：一个是三位的分数，一个是两位的分数， 又都没对齐，眼睛要分别读两遍才知道谁紧张。要么都写成「60 / 100」，要么都缩成「60%」。

2. 名次从 6929 掉到 512，同样的字体宽度，为什么你希望它靠右而不是靠左？

靠右时个位在同一列，位数变化会表现成「向左长出来」——从 4 位变 3 位，你能一眼看出数字变短了； 靠左时个位在动，位数变化只能靠数。
