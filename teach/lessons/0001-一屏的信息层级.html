第 1 课 · 信息层级

一屏只能有一件事

你的 P2 第一屏，现在有 六维数值、体力、段位、名次、金钱、伤病、教练信任、三个空槽、结周、退役、跳到下一年、一句旁白。 十三件东西，一样大小，一样颜色。

玩家在这种屏上会做一件事：找不到该按哪里。不是难看，是读不出来。

这一课只有一条规则：一屏之内，只有一件事可以拿到「最大的字号 + 最亮的位置」，其余全部退到第二层。你要能一句话说出那件事是什么。

三个数字，先背下来

数值为什么是这个数
点击目标 44 × 44 px（硬底线 24） WCAG 2.2 规定最低 24×24 CSS px；Apple 的 iOS 按 44×44 pt 做。手机上手指面积约 9mm，低于 44 就容易点偏。
正文行高 1.75 中文字面比英文满，行距要更松；1.5 在手机竖屏上会挤成一片。
间距单位 4 的倍数
（8 / 16 / 24 / 32）		 所有边距取同一个基数，改一个数不会连锁打架。Material 用的是 8dp 栅格。

字号不是「大一点小一点」，是几档。你现在写 P3 规格时，先定档，再往内容上套：

  • 32 / 22 / 17 / 13 —— 这四档够用一辈子（标题 / 段落标题 / 正文 / 注释）。
  • 不要用 15.5、18.3 这种数。档位一多，层级就没了。

两道题，答完再往下

  1. 你的 P2 第一屏上，只有一件事能当「主」。是哪件？
    「三个格子都没排」——因为这一屏存在的唯一理由是让你去排格子。数值是给排完之后看的，不是给现在看的。
  2. 如果主信息定成「第 1 年 · 第 1 周」，会出什么问题？
    时间不是你能操作的东西。主信息必须是「你要做但还没做的事」，否则玩家读完标题就没有下一步。

  • 你眼里最大的那个元素——它配不配
  • 最小、但你其实最需要点的那个元素
  • 两处你觉得「挤」的地方

先别改。把这个清单留着，第 2 课我们会用「间距」把第三项拆掉。

一手来源

  • WCAG 2.2 · SC 2.5.8 Target Size (Minimum) —— 24×24 CSS px 或足够间距。
  • Apple HIG · Buttons —— 触摸目标 44×44 pt。
  • W3C · Requirements for Chinese Text Layout —— 中文标点、行首行尾的规则。
